# S2J Query Pinned - プラグイン仕様 (ドラフト)

採用・合意前の設計メモとして `docs_mod/` に置き、確定後は `docs/SPEC.md` に移行します。状態はドラフトです。記録日は2026-10-04です。

計算の正は [S2J Query Pinned Service のサービス仕様](https://github.com/stein2nd/s2j-query-pinned-service/blob/main/docs_mod/service_spec.md) です。本書は、WordPress 側の設定、ピンのメタ、上限の計算、ダイアログ、Archive クエリーを定義します。

## 概要

本プラグインは、一覧の先頭にピン留めしたコンテンツを置き、残りを別の順で並べます。ピンを先頭にする組立、ページングでの重複除外、上限を超えた追加を結果に含めないことは、S2J Query Pinned Service が行います。

スラッグは `s2j-query-pinned` です。ライセンスは GPL-3.0-or-later です。テキストドメインは `s2j-query-pinned` です。

kis-core は本機能の本体にしません。KIS のサイトは、本プラグインを有効化して使います。ニュース一覧などは、その利用の一つです。

## 位置付け

| 層 | 名称 | 役割 |
| --- | --- | --- |
| 計算 | [s2j-query-pinned-service](https://github.com/stein2nd/s2j-query-pinned-service) | ピン優先の ID 列、ページング、上限。WordPress を知らない。日付の種類を持たない |
| 副作用 | **本プラグイン** | 設定、メタ、上限の計算、ダイアログ、Archive の `WP_Query` |
| 残りの更新日 | [s2j-content-dates-service](https://github.com/stein2nd/s2j-content-dates-service) | 非ピン集合の更新日。本サービスとは Composer でつながない |

残りの並びが更新日のときは、本プラグインが Content Dates の結果を作り、その順を Query Pinned Service に渡します。Query Pinned Service は Content Dates を知りません。

## 目的

初版で、管理者が次を終えることです。

* コンテンツタイプごとに、ピン留めのチェックを出すかを決める。
* Archive を持つタイプでは、ピンの有無による絞り込みとソートを足すかを決める。
* 編集画面で、その1件をピンする。上限を超える操作は、その場で外すピンを選ばせる。
* 一覧にピン留め列を出すかを決める。サイトの初期値は出さない。すべてのタイプで出す指定と、タイプごとの除外ができる。
* ピン留めチェックが on のタイプの Archive で、ピンを先頭に、残りを従来の順に出す。

一覧ごとに別のピンセットは持ちません。タイプが off のとき、そのタイプの個別ピンも off です。タイプが on で、ピン総数が上限未満の間は、個別の on/off に従います。

## 非目標 (初版)

* ピン同士を、チェックした順や手の並びで置くこと。順序は、渡した日付の新しい順です。
* 上限を超えたとき、日付の新しい順で既存ピンを自動的に外すこと。
* 固定の初期値3、推奨レンジ、ライブラリやプラグイン設定のハード上限。
* テーマの色、テンプレート階層。
* 公開日と更新日の算出そのもの。それは S2J Content Dates です。

## サービスとの境界

本プラグインは、ID 列、各 ID の日付、ページサイズ、オフセット、上限をサービスに渡します。戻りは、そのページの順序付き ID 列です。

| 本プラグイン | サービス |
| --- | --- |
| ピンの ID と、比較用の日付を渡す | ピンを先頭にし、ピン同士は日付の新しい順にする |
| 非ピンの ID を、すでに決めた順で渡す | 残りはその順のまま、ページサイズまで取る |
| 「設定 > 表示設定」の表示件数から上限を計算して渡す | 表示設定は読まない。超える追加は結果に含めない。切り詰めない |
| ページ番号と表示件数を、ページサイズとオフセットにする | 2ページ目以降でピンを繰り返さない |
| `WP_Query` を、戻った ID 順に組む | `WP_Query` は組まない |

上限を超える ID 列は、サービスに渡しません。

## 設定

画面は「設定 > ピン留め」です。操作できるのは `manage_options` を持つユーザーです。

表は `WP_List_Table` 相当です。1行が1コンテンツタイプです。見出しは「カスタム投稿タイプ」ではなく **コンテンツタイプ** です。Content Dates の表と同型です。

| 列 | 内容 |
| --- | --- |
| コンテンツタイプ | 表示名と登録名 |
| ピン留めチェックを出す | on/off |
| Archive にピン有無の絞り込みとソートを足す | on/off。`has_archive` がないタイプは、チェックを置かず無効 |
| 一覧にピン留め列を出す | on/off。`attachment` も有効。そのタイプの一覧はメディアライブラリ |

行に出すタイプは、`page`、`post`、`public` または `show_ui` の CPT、`attachment` です。`show_ui` だけで `public` ではない CPT も出します。管理画面に一覧があるタイプです。内部タイプは出しません。`page` と `attachment` の Archive 列は無効です。

表の上に、「一覧にピン留め列を出す」を置きます。選択肢は「出さない」と「すべてのタイプで出す」です。保存先はオプション `s2j_query_pinned_column` で、値は `off` または `all` です。キーがない間は `off` です。

表の上に、次の文を常時出します。表示件数がすでに2以上でも隠しません。

> 「アーカイブページに表示する最新の投稿数」は、2以上にしてください。

保存先はオプション `s2j_query_pinned_types` です。タイプ登録名をキーにし、値は `show_pin`、`show_archive`、`show_column` です。それぞれ `true`、`false`、またはキーなしです。

新規タイプのデフォルトは off です。`show_column` 以外は、キーがない間は off として読みます。登録された瞬間には書きません。利用者がその行のチェックを変えたときだけ、そのタイプのキーに on または off を保存します。登録が消えたタイプのキーは残します。

`show_column` は、サイトの値と合わせて読みます。サイトが `off` のとき、`true` のタイプにだけ列を出します。キーなしと `false` は出しません。サイトが `all` のとき、キーなしと `true` のタイプに出します。`false` のタイプには出しません。`all` の間に登録されたタイプは、除外するまで出ます。`show_pin` が off のタイプには、列の設定が出す側でも列を出しません。

## 上限

同一タイプのピン上限は、「設定 > 表示設定」の「アーカイブページに表示する最新の投稿数」(`posts_per_page`) の1/2です。端数は切り捨てます。タイプごとに別の数値は持ちません。勘定だけをタイプの中で行います。

表示件数が10なら上限は5、1なら上限は0です。上限が0のタイプではピンできません。クエリー側で変えた表示件数は使わず、この設定値だけを使います。

保存済みのピンが、設定変更で上限を超えたときは、日付順で外しません。そのタイプの Archive にはピンを渡さず、設定画面に「このタイプのピンは N 件を超えています。外してください」と出します。

## 個別のピン

メタ名は `_s2j_pinned` です。ピンするとき `1` を書き、外すときメタを消します。`0` は書きません。

チェックを出す場所は、ブロックエディターの文書サイドバーと、列の設定が出す側の一覧です。投稿と固定記事の一覧は、そのタイプの投稿一覧です。添付ファイルの一覧は、メディアライブラリです。タイプの `show_pin` が off のときは、チェックを出さず、メタが残っていてもピンとして読みません。

その投稿を編集できるユーザーが、チェックを変えられます。

## 上限を超えたとき

上限を超えてピンしようとした時点で、その操作は保存しません。ダイアログで、そのタイプのピン済み一覧を出します。

* 警告は「このタイプでは N 件までピンできます」です。N は、上の上限です。
* 本文は「この記事をピンするには、次から外す記事を選んでください」です。
* 初期状態は、ピン済みのチェックが付いた一覧です。外す記事だけチェックを外します。
* 「すべて外す」は、この一覧のチェックをすべて外します。実行前に「ピン留めをすべて外します。よろしいですか ?」と確認します。
* 確定ボタンのそばに、足りない件数を出します。例は「あと1件、ピン留めを解除してください」です。選択のたびに件数を変えます。
* 外した数が足りて、新しい1件を足しても N 件以下になるまで、確定は押せません。足りたとき、その一文を消し、確定を押せるようにします。
* キャンセルすれば、ピンは変えません。

## ピン同士の日付

サービスに渡す比較用の日付は、次のとおりです。

* Content Dates がそのタイプで更新日を出しているときは、集約後の更新日。
* そうでなければ公開日。
* Content Dates が無効なら、公開日。

サイトのタイムゾーン付きの値にします。チェックした時刻は使いません。

## Archive

`show_pin` が on で、保存済みピンが上限以内のタイプでは、メインの Archive クエリーを次の順で組みます。

1. ピンの ID と、比較用の日付を集める。
2. 非ピンの ID を、そのクエリーが本来使う順で集める。`orderby=modified` のときは、Content Dates のソートキーの順にする。
3. ページサイズとオフセット、上限とともにサービスへ渡す。
4. 戻った ID 順を、そのページの `WP_Query` にする。

`show_archive` が on のタイプだけ、追加のクエリー変数を受けます。デフォルトの Archive は、ピンを先頭にした組立のままです。

* `pinned=1` はピンだけ、`pinned=0` はピン以外だけ。
* `orderby=pinned` は、ピンを先頭にする組立を明示します。`show_pin` が on のメイン Archive では、この変数がなくても先頭にします。

`show_pin` が off のタイプでは、ピンを先頭にせず、このクエリー変数も無視します。

固定記事にメインの Archive はありません。`show_pin` が on の固定記事は、Query Loop ブロックで「ピン留めを先頭にする」が on のときだけ、同じ組立を使います。ブロックを置いたときの初期値は off です。そのブロックだけ、on にできます。

## メディア

`attachment` の行は表にあります。デフォルトは off です。`show_pin` が on のとき、添付ファイルの編集画面にピンのチェックを出します。メディアライブラリのピン留め列は、上の列の設定が出す側のときだけ出します。

## 設計方針

[kis-wordpress エコシステム仕様](https://github.com/stein2nd/kis-wordpress/blob/main/docs_mod/specs.md) および [wp-plugin-spec](https://github.com/stein2nd/wp-plugin-spec) に従います。ID 列の組立はサービス側の純関数です。本プラグインはアダプタです。

設定画面、メタ、ダイアログ、`WP_Query` は本プラグインに置きます。

| 借用する原則 | 本プラグインでの意味 |
| --- | --- |
| 依存の向きは外 → 内 | 画面とクエリーがサービスを呼ぶ。サービスは WordPress を呼ばない |
| 内側はビジネスルール | 結合、ページング、上限の適用はサービス |
| 外側は詳細 | オプション、メタ、ダイアログ、Archive |

Composer で `s2j/query-pinned-service` を require します。参照は [S2J Slug Generater](https://github.com/stein2nd/s2j-slug-generater) が [`s2j/similarity-service`](https://packagist.org/packages/s2j/similarity-service) を Packagist の名前だけで require するのと同じです。`repositories` に `VCS` も `path` も書きません。Content Dates への Composer 依存は持ちません。更新日が必要なクエリーのときだけ、Content Dates のプラグインが有効ならその結果を受け取ります。

アンインストールでは、オプション `s2j_query_pinned_types` と `s2j_query_pinned_column`、メタ `_s2j_pinned` を消します。投稿は消しません。

## 実装順

1. 本ドラフトの合意。
2. 設定テーブル、常時の注意文、変えた行だけの保存。
3. `_s2j_pinned`、エディターのチェック、一覧のピン留め列、上限ダイアログ。列はサイトの初期値では出さない。`all` と、タイプの `show_column` で出し分ける。
4. メイン Archive を、サービスの ID 順にする。
5. `pinned` と `orderby=pinned`。Content Dates が有効なときの非ピンの更新日順。
6. 添付ファイルの編集画面と、メディアライブラリのピン留め列。

## 本ドラフトの提案

合意前の提案です。

* メニューは「設定 > ピン留め」。表の見出しは「コンテンツタイプ」。
* 設定キーは `s2j_query_pinned_types`。メタ名は `_s2j_pinned`。
* 上限はサイトの `posts_per_page` の1/2 (切り捨て)。クエリー個別の表示件数は使わない。
* 保存済みが上限を超えたタイプは、Archive にピンを渡さない。自動では外さない。
* ピン同士の比較日は、Content Dates が更新日を出しているタイプでは集約後の更新日、それ以外は公開日。
* `show_pin` が on のメイン Archive は、追加のクエリー変数がなくてもピンを先頭にする。
* 「すべて外す」の確認文は「ピン留めをすべて外します。よろしいですか ?」。
* 表の行は、`page`、`post`、`public` または `show_ui` の CPT、`attachment` です。`show_ui` だけで `public` ではない CPT も出します。
* 固定記事の Query Loop は、「ピン留めを先頭にする」の初期値を off にする。そのブロックだけ on にできる。
* 一覧のピン留め列は、初期値では出さない。`s2j_query_pinned_column` が `all` のときは、`show_column` が `false` のタイプを除いて出す。`off` のときは、`show_column` が `true` のタイプだけに出す。`show_pin` が off のタイプには出さない。添付ファイルの列はメディアライブラリに出す。
